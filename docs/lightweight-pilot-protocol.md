# Lightweight development pilot v1 - 2026-10-28

This protocol is frozen by the run's saved SHA256 before live execution. It supplements the main draft; it is not main-study preregistration. All tasks are researcher-created controlled tasks. No natural work, published reproduction or production-frequency claim is implied.

Application: private loopback HTTP job service with SQLite transactions. One intended job per task, title `Check dataset manifest`, priority `normal`, pending state. Tools: create_job and list_jobs. Tools cannot access arbitrary files, shells or the public network. Independent read-only SQL audit requires exactly one job with the expected values and exactly one linked committed effect. Additional effect IDs for this one-job goal are duplicate committed effects. This simple task validates execution and instrumentation; it does not fulfill cross-workflow or realistic-benchmark coverage.

First cohort: one nominal task per requested model using the minimal loop; sequentially, without downloads or injected faults. Then one matched nominal task per model with an established graph runner if integration succeeds. Do not select subsequent tasks based on model success. First and subsequent cohorts remain distinguishable. No automatic transport retry; each new model-requested tool action gets its own attempt ID and parent model-call ID. Errors become tool results; model-requested repetition is recorded, not automatically classified unnecessary.

Defaults: 4096 context, 512 output-token cap, temperature 0, seed 20261028, thinking disabled for Qwen (explicit configuration change from old smoke test), one inference request, one loaded model. Maximum 4 model calls, 8 tool actions, 120 seconds per call, 300 seconds per task. Graph recursion bound 12. Application requests time out after 5 seconds. Record model digests, response token counts, done_reason and duration breakdown. Truncation is unknown unless supported by runtime evidence; budget termination is not an application failure.

Parent supervisor samples host RAM/CPU and process RSS, with GPU samples where available. Stop before load below 1 GiB available RAM; stop an active worker if host available RAM falls below 1 GiB, or on task deadline. Resource sampling has finite resolution and cannot guarantee zero transient overshoot. Preserve cancellations, worker errors and final SQL state. Unload only the study model after worker exit; inspect actual loaded state. Do not kill unrelated processes or weaken the gate. Report sampling gaps and instrumentation errors. No target outage/recovery claim from this cohort.

Direct validation conditions are separate: ordinary direct call, deliberate reply loss after commit plus one explicit direct-client retry with/without an idempotency key, and known incorrect SQL states/reset tests. Every intervention is labelled live_model=false. Native idempotency protects application effects; identical-argument suppression is not substituted. These do not estimate any natural failure rate.

Interpretation: report every attempted task, correctness from SQL, committed duplicates, model/tool counts, duration and cancellations. Do not derive confidence in production reliability from one task per model. Framework arms use shared model/tool code and equal budgets; they evaluate the explicit graph integration, not every default agent feature. A larger main study still requires workload realism, task sampling, statistical planning and service-impact instrumentation.
